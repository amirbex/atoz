# AtoZ Content Engine · موتور محتوای AtoZ

موتور محتوای محلی و بازتولیدپذیر برای دریافت برنامهٔ واقعی، ساخت پروندهٔ محتوا، تولید متن‌های اولیه، رندر SVG/PNG و ساخت پیش‌نمایش موشن. خروجی هفتهٔ اول در `content-output/week-01/` نوشته می‌شود؛ پوشهٔ قدیمی `پیش انتشار/ماه اول/هفته اول/` منبع برنامه و آرشیو قبلی است و این موتور آن را تغییر نمی‌دهد.

## مسیر داده

```text
پیش انتشار/ماه اول/هفته اول/plan.json
           │  اعتبارسنجی برنامه و روابط
           ▼
tools/run_content_engine.py
           └── content-output/week-01/
               ├── index.html                  تابلوی کل هفته
               ├── plan.json + assets/
               ├── content-items/ATZ-C-…/
               ├── {روز}/
               │   ├── index.html              تابلوی آن روز
               │   ├── 01-reels/               صفحهٔ هر ریل + لینک ویدئو
               │   ├── 02-carousels/           صفحهٔ هر کاروسل + گالری اسلایدها
               │   ├── 03-posts/               پست‌های تکی و گرافیک‌ها
               │   ├── 04-stories/             استوری‌ها
               │   ├── 05-web-telegram/        پیش‌نویس متن/مقاله
               │   └── ATZ-C-…/ATZ-D-…/        رسانه و فایل‌های canonical
               ├── motion-lab/
               └── content-engine-manifest.json + generated-file-index.json
```

- برنامهٔ منبع، برنامهٔ ۲۸ محتوای مادر و ۸۴ تحویل است؛ عددها از فهرست تحویل‌ها محاسبه می‌شوند، نه از سهمیهٔ روزانهٔ ثابت.
- دارایی‌های ثابت از `brand/tokens.json`, `brand/design-system.json`, `logo/primary/`, `logo/subbrands/`, `logo/motion/` و فونت‌های مجاز `tools/fonts/` مصرف می‌شوند.
- هر خروجی در مسیر یکتای روز/محتوا/تحویل نگهداری می‌شود. SVG منبع قابل‌ویرایش است؛ PNG و MP4 خروجی رندرند.
- زمان انتشار، دامنه، شناسهٔ شبکه و تأیید مالک تولید نمی‌شود. پیوندهای نامعلوم با برچسب تأییدنشده باقی می‌مانند.
- وضعیت خروجی‌ها پیش‌نویس است. ذخیرهٔ یک بررسی در داشبورد، انتشار یا ارسال به شبکه انجام نمی‌دهد.

## نصب و اجرا

پیش‌نیازها: Python 3.11، Node.js و npm. یک بار وابستگی‌های محلی را نصب کنید:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r tools/requirements.lock
npm --prefix tools install
```

سپس بستهٔ هفتهٔ اول را بسازید و داشبورد محلی را اجرا کنید:

```bash
.venv/bin/python tools/run_content_engine.py
.venv/bin/python tools/serve_content_studio.py --host 0.0.0.0 --port 4173
```

برای رندر کامل ریل‌ها از FFmpeg بستهٔ `imageio-ffmpeg` استفاده می‌شود. `--skip-video` فقط در صورت نیاز به حذف MP4های ۱۶ ریل در دسترس است؛ storyboardهای قابل‌ویرایش حفظ می‌شوند.

گزینه‌ها:

```bash
.venv/bin/python tools/run_content_engine.py --help
```

موتور از بازنویسی ناخواستهٔ خروجی جلوگیری می‌کند. برای آزمایش، `--out` را به یک پوشهٔ موقت/نسخهٔ تازه بدهید؛ هیچ گزینه‌ای پوشهٔ آرشیوی قبلی را پاک نمی‌کند.

## داشبورد

`/content-engine/dashboard/` یک استودیوی RTL واکنش‌گراست: خلاصه و اختلاف شمارش، تقویم روزانه، فیلتر محتوا، پروندهٔ تحویل، پیش‌نمایش/دانلود منبع، کپی کپشن، صف بازبینی، دریافت ایدهٔ ساختاریافته و آزمایشگاه موشن. وضعیت بازبینی به‌صورت محلی در `content-output/week-01/review-state.json` ذخیره می‌شود.

## انضباط تولید

1. ایدهٔ مادر با مسئله، مخاطب اصلی، پیام مرکزی، ستون، منبع و سطح شواهد ثبت می‌شود.
2. موتور قالب اولیه می‌سازد؛ متن ادعایی یا دادهٔ فرضی به‌صورت واقعیت منتشر نمی‌شود.
3. renderer قالب SVG/HTML را با لوگو، رنگ، فونت و حریم امن AtoZ می‌سازد.
4. انسان ادعاها، کپی، منابع، CTA، زمینهٔ حقوقی و خوانایی را تأیید می‌کند.
5. زمان‌بندی/بارگذاری همچنان دستی است؛ دکمهٔ تأیید داشبورد فقط ثبت بازبینی محلی است.

## موتورهای موشن

کتابخانهٔ محلی `motion-recipes.json` دستورهای پارامتری خودمان را نگه می‌دارد: نمودار داده‌محور، متن جنبشی، reveal/transition، لوگوموشن و anatomy مرحله‌ای. دموی anatomy با یک مدل دادهٔ مشترک، قطعه‌ها را به‌صورت seekable حرکت می‌دهد. کدهای خروجی با SVG/HTML و FFmpeg در محیط فعلی قابل رندر هستند. برای نصب/فعال‌سازی Remotion یا HyperFrames نیازی به کلون‌کردن پروژه‌های مرجع نیست؛ قالب‌ها و داده‌ها adapter-friendly هستند و ادغام runtime آن‌ها در این نسخه اختیاری/غیرفعال است.

## الگوهای مرجع و انتساب

از مخزن AtoZ CMS برای تفکیک workspaceها (اتاق فکر، ورود سند، صف تولید، استودیو و مخزن برند)، از OpenDesign برای local-first بودن و استفاده از design system، از Remotion برای مدل timeline/دادهٔ React، از HyperFrames برای ترکیب seekable وب و رندر deterministic، و از Anatomy برای توضیح یک سامانه با قطعاتی که از یک مدل داده مشترک می‌آیند الهام گرفته شده است. کد، دارایی یا recipe از آن مخزن‌ها کپی/وارد نشده؛ رسپی‌های این پوشه مستقل و مختص AtoZ هستند.
